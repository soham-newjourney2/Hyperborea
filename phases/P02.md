# P02 — Pilot boundary + OSM buildings, roads, facilities
**Day:** Fri 6 Nov · **Depends on:** P01 · **Refs:** planning §6, DATA_SOURCES `osm`

## Goal
A chosen ~1–2 km² Salt Lake pilot boundary and a GeoPackage with buildings, roads, facilities — every feature carrying provenance.

## Steps
1. `pipelines/scan_candidates.py`: for 2–3 candidate polygons/bboxes (e.g. **A** Sector V — IT/commercial, good development story; **B** a Sector I–III residential block cluster bordering a canal — good drainage story; **C** user's choice) fetch with osmnx (`ox.settings.cache_folder` → `local/cache/osmnx`) and print a compact table: area km², building count, % buildings with height/levels, road km, hospitals / schools / fire stations / police, `power=*` features, `waterway=*` features, metro stations.
2. **Ask the user to pick** (show the table + Teammate A's notes if available). Save the boundary as `data/curated/boundary.geojson` (curated) and log the choice in DECISIONS (D-17).
3. `pipelines/fetch_osm.py`: fetch for boundary **+ 2 km buffer** (needed later for hospitals/routing outside the pilot): buildings, drive+walk road network (save graph as GraphML in `data/raw/osm/`), amenities (hospital, clinic, school, college, fire_station, police), `railway=station` / metro, `power=*`, `waterway=*`, `landuse=*`. Raw files are immutable and timestamped.
4. `pipelines/normalize_osm.py` → `data/processed/hyperborea.gpkg` layers: `boundary`, `buildings`, `roads`, `facilities`, `waterways`, `landuse`, `osm_power` (kept for P10). For each feature: `asset_id` (`bld_osm_w<id>`, `rd_osm_<u>_<v>_<k>`, `fac_osm_<type><id>`), `asset_type`, `name`, `data_status=observed`, `source_id=osm`, `observed_at` = extract time, `ingested_at`, `confidence`, `assumptions`, `attrs`. Building height: `height` tag → observed; else `building:levels × 3.2 m` → modelled; else 9 m default → `height_status=assumed`. Flag `in_pilot` (inside boundary) vs buffer.
5. Validate: fix invalid geometries (`make_valid`), drop duplicates, compute areas/lengths in EPSG:32645, store EPSG:4326.
6. Quick preview PNG (matplotlib) → `presentation/screens/P02_preview.png`.
7. DATA_SOURCES entry for `osm` (accessed date, coverage, attribution).

## Out of scope
Drainage, power modelling, map UI.

## Acceptance (showcase)
- Candidate table shown, boundary chosen by the user.
- GPKG layer counts printed; preview PNG shows buildings + roads inside boundary.
- 100% of features have `asset_id`, `data_status`, `source_id`.
