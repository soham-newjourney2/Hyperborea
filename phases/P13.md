# P13 — CV layer + ML surrogate risk model
**Day:** Wed 11 Nov · **Depends on:** P08, P11 · **Refs:** D-11, VISION §11

## Goal
Two honest AI components (open-source, free), each with a model card: a pretrained CV water-segmentation layer and a fast ML surrogate of the flood engine.

## Steps
**Setup (offline only, not deployed)**
1. `requirements-ml.txt`: torch + torchvision from the CUDA **cu128** wheel index (works on RTX 4050 and RTX 5050), huggingface_hub; check `torch.cuda.is_available()`. All weights/caches in `local/hf`, `local/torch`. Record GPU + versions in LOG.

**A. CV — surface-water segmentation (time-box 3 h)**
2. Candidate: NASA-IBM **Prithvi-EO** Sen1Floods11 fine-tuned checkpoint (Hugging Face; expected Apache-2.0 — verify repo name, licence, inference instructions via Context7/model card before download). Input: Sentinel-2 L2A bands B02, B03, B04, B8A, B11, B12 for the pilot (Planetary Computer), one dry-season + one post-monsoon low-cloud scene.
3. `pipelines/cv_water.py`: tile → infer → water mask → polygons (min area filter) → GPKG layer `cv_water` (`data_status=modelled`, `source_id=cv_water`) + PNG overlay.
4. **Fallback if not working by the time-box:** NDWI (McFeeters) threshold → same layer, labelled "spectral index — not ML". Log the switch in DECISIONS.
5. Caveats in model card + UI: 10–20 m pixels can't see street waterlogging; monsoon cloud cover; not validation of the flood engine.

**B. ML surrogate (sklearn — runs on the hosted API)**
6. `pipelines/train_surrogate.py`: Latin-hypercube ~2,000 runs of `run_flood` (rain 5–120 mm/h, duration 0.5–6 h, condition scale 0.6–1.2) → per-drain rows: catchment area, C, capacity, upstream area, slope, condition, rain, duration → label `overloaded` + `load_ratio`.
7. Split by **spatial blocks of drains** (no leakage); `HistGradientBoostingClassifier`; baseline = rain-intensity threshold rule. Metrics: precision, recall, F1, ROC-AUC on held-out blocks → `models/model_cards/surrogate.md` + `models/surrogate.joblib` (< 5 MB).
8. Endpoint `/ml/quickscan` (instant overload probability map for slider values — label "surrogate of the rule engine, trained on simulated runs; not validated on real events") and `/models` (cards).
9. UI: **AI Quick-scan** toggle in Disaster Lab (slider → instant map), model-card drawer (metrics vs baseline, feature importances, licence, limitations); CV layer toggle in Environment.

## Out of scope
Fine-tuning, GNNs, claims of real-world accuracy.

## Acceptance (showcase)
CV water layer visible with its badge; Quick-scan slider updates instantly and matches full engine broadly; model cards show honest metrics and licences.

## Tests
Surrogate loads and predicts in < 200 ms for all drains; metrics file exists; CV layer props complete; no torch import in backend runtime.
