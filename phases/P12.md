# P12 — Roads / commute accessibility
**Day:** Tue 10 Nov · **Depends on:** P02, P08 · **Refs:** VISION §9.4

## Goal
Travel-time accessibility to critical services and how the flood scenario degrades it — a strong extra hop in the cascade.

## Steps
1. `engine/access.py`: load the drive graph (pilot + 2 km buffer) from `data/raw/osm/*.graphml` (or a processed copy); `osmnx.add_edge_speeds` / `add_edge_travel_times` (free-flow, OSM maxspeed or class defaults — **not live traffic**).
2. Multi-source Dijkstra from hospitals, fire stations, metro/rail stations → per-building travel time (min) to nearest of each; precompute baseline at startup.
3. Scenario: remove edges whose road is `impassable` in a flood result (impaired = speed × 0.5) → recompute → Δ minutes, newly isolated buildings, facilities with no route. Add an access hop to the flood explanation chain ("block X → nearest hospital 4 → 11 min").
4. Development: road-access check uses travel time to hospital/fire station.
5. Endpoint `/access/summary?result_id=` (baseline or scenario).
6. UI: buildings coloured by travel time (toggle hospital/fire/metro); scenario Δ view; isolated buildings highlighted; legend states "free-flow estimate".

## Out of scope
Live traffic APIs, public transport schedules.

## Acceptance (showcase)
Baseline accessibility map; run `extreme` → Δ map shows longer hospital access and isolated pockets, linked from Why? chain.

## Tests
Travel times > 0; removing edges never decreases travel time; buildings with no path flagged, not zero.
