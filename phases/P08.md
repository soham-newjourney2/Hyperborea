# P08 — Disaster intelligence: extreme-rainfall cascade
**Day:** Mon 9 Nov · **Depends on:** P05, P07 · **Refs:** planning §7 (all formulas), §8, VISION §8.3–8.5

## Goal
The signature live demo: pick a rainfall scenario → see overloaded drains, ponding, impassable roads, exposed buildings and cut-off facilities — each with a "Why?" chain.

## Steps
1. `backend/engine/flood.py` — `run_flood(graph, store, params) -> Result` on a **scenario overlay** (never mutate baseline):
   1. Runoff per catchment (rational method, preset or custom `rain_mm_h`, `duration_h`; `condition_scale` multiplies condition factors).
   2. Route in topological order on `DRAINS_TO`: inflow = own runoff + upstream outflows; outflow = min(inflow, effective capacity); overflow = excess; `load_ratio = inflow / capacity`.
   3. Ponding depth per catchment from overflow volume (§7), capped.
   4. Roads `ADJACENT_TO` overflowing drains or inside ponded catchments: impaired ≥ 0.15 m, impassable ≥ 0.30 m.
   5. Buildings `LOCATED_WITHIN` ponded catchments with depth ≥ plinth 0.45 m → exposed.
   6. Facilities: all `DEPENDS_ON` roads impassable → access cut (P12 refines with routing; P10 adds power).
   7. Risk index per affected asset (§7, weights in `config/risk.yaml`), labelled *index, not probability*.
   8. Explanation object per affected asset (§7) with the hop-by-hop path and numbers.
2. `engine/rules.py`: thresholds + assumptions from `config/` (single source; UI shows them).
3. Endpoints: `POST /scenarios/flood` → `{result_id, params, summary{drains_overloaded, road_km_impaired/impassable, buildings_exposed, facilities_affected}, layers{drains, roads, catchments, buildings}, affected[], assumptions[], data_status:"modelled (simulated inputs)"}`; cache results by params hash.
4. Frontend **Risk & Disaster Lab**: preset picker + sliders (rain, duration, drain condition), Run; banner "Scenario-based estimate — not a prediction"; map recolours drains by load ratio, roads by passability, ponding depth on catchments, exposed buildings highlighted; results list sorted by risk; **Why? panel**: chain view (rain → drain → ponding → road → facility) with inputs, formulas, assumptions, data status, "data that would improve this".
5. Fixed demo: save `data/snapshots/flood_heavy.json`, `flood_extreme.json`; snapshot fallback in UI.

## Out of scope
Hydraulic calibration, SWMM, time-stepped hydrographs.

## Acceptance (showcase)
`extreme` preset → visible cascade on the map within ~2 s; click an impassable road → Why? chain back to the overloaded drain and the rain input with numbers; `moderate` shows few/no overloads.

## Tests (VISION §19.3)
Rain below capacity → zero overloads; overloads monotonic non-decreasing with rain; baseline graph unchanged after run; simulated labels preserved in result; deterministic for same params; snapshot expected-output test for `heavy`.
