# P09 — Development assessment + what-if A/B/C
**Day:** Mon 9 Nov · **Depends on:** P08 · **Refs:** planning §7 norms + verdict, VISION §10

## Goal
Draw or pick a proposed building → transparent multi-dimension check → compare A (no upgrades), B (with upgrades), C (alternative site).

## Steps
1. `config/norms.yaml` (planning §7) with source note per value; `data/curated/sites.geojson`: 2–3 candidate sites inside the pilot (vacant/open/brownfield from OSM `landuse` or imagery) — ask the user to confirm them.
2. `backend/engine/development.py` — `assess(geometry|site_id, use, floors, upgrades[], design_preset)` on an overlay:
   - Derived: footprint m², BUA = footprint × floors, height, occupants, water demand (kL/day), electrical demand (kVA), added runoff (ΔC × i × A).
   - Checks → `pass | conditional | fail | insufficient_data` with numbers:
     **Drainage** (receiving drain headroom under design preset incl. added runoff) · **Flood exposure** (ponding depth at site from P08 result) · **Road access** (nearest road class + distance) · **Critical facilities** (distance to nearest hospital/fire station) · **Electrical** (`insufficient_data` until P10) · **Water supply** (`insufficient_data` — no public supply data; say so) · **Land use** (OSM landuse compatibility).
   - Verdict rule (planning §7) + transparent weighted index with weights shown.
   - Upgrades (B): upsize receiving drain one class · on-site detention/RWH tank (peak runoff −40%, assumed) · new/up-rated transformer (P10).
   - Graph overlay: proposed node + `PROPOSED_ADJACENT_TO`/`LOCATED_WITHIN`/`ACCESSIBLE_VIA` edges (scenario only).
3. Endpoints: `POST /development/assess`, `POST /development/compare` (list of options → side-by-side).
4. Frontend **Development** panel: Draw tool (click points on globe, double-click to close; or pick preset site), use/floors inputs, upgrades checkboxes, design-rain preset; proposed building extruded in purple (simulated); result card with verdict label (exact wording from §7), per-dimension rows with numbers + assumptions + data status; **Compare** view A/B/C table + "what changed" notes.

## Out of scope
Statutory FAR/bye-law checks, cost estimation, optimisation (post-qualification).

## Acceptance (showcase)
Draw a 10-floor commercial block → *Conditionally suitable* (drainage) → tick detention tank + drain upsize → verdict improves → compare with site C, all reasons visible. Never says "approved".

## Tests
Assessment doesn't alter baseline layers/graph; same inputs → same output; verdict rule table tests; insufficient-data path; upgrades reduce drainage load.
